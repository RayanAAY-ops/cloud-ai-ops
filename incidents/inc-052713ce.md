# INC-052713ce: Lambda function cloudops-ai-app-dev cannot write to DynamoDB due to missing IAM permissions for dynamodb:PutItem action.

**Severity:** high

> Opened automatically by cloudops-ai. This PR only documents the incident:
> **no code or infrastructure is changed.** Apply the fix yourself, then merge.

## 🔴 Error

```
[ERROR] ClientError: An error occurred (AccessDeniedException) when calling the PutItem operation: User: arn:aws:sts::<x>:assumed-role/cloudops-ai-app-dev-exec-role/cloudops-ai-app-dev is not authorized to perform: dynamodb:PutItem on resource: arn:aws:dynamodb:eu-west-<x>:<x>:table/shop-items-cloud-ops-ai-app-dev because no identity-based policy allows the dynamodb:PutItem action
```

## 💥 Impact

All requests to the Lambda function that attempt to write items to the DynamoDB table shop-items-cloud-ops-ai-app-dev are failing with AccessDeniedException. This blocks data ingestion and affects all users/services depending on this write functionality.

## 🔍 Root cause

- **95%** IAM policy for DynamoDB PutItem was never added to the Lambda execution role
- **5%** DynamoDB policy was recently removed from the role (though no CloudTrail changes detected in 24h window)

**Evidence**

- Error logs show AccessDeniedException for dynamodb:PutItem on shop-items-cloud-ops-ai-app-dev table in all recent invocations (2 errors out of 2 invocations in last hour)
- IAM role cloudops-ai-app-dev-exec-role only has AWSLambdaBasicExecutionRole attached (CloudWatch Logs only)
- No inline or additional policies attached to the role
- Permission check confirms implicit deny on dynamodb:PutItem action for the target table
- Application code at /var/task/app.py:21 calls table.put_item() which requires IAM permissions

## 🛠 Proposed fix

Attach an IAM policy to the role cloudops-ai-app-dev-exec-role that grants dynamodb:PutItem permissions on the table arn:aws:dynamodb:eu-west-1:523987126142:table/shop-items-cloud-ops-ai-app-dev. This can be done by either: (1) creating a custom inline policy on the role with Action: dynamodb:PutItem and Resource: [table ARN], or (2) attaching an existing policy like AmazonDynamoDBFullAccess if a broader scope is acceptable, or (3) using a more restrictive managed policy. Additionally, consider whether GetItem, Query, Scan permissions are also needed for the application's full functionality.

## ❓ Uncertainty

No recent changes detected in CloudTrail, so we cannot determine if this is a misconfiguration from initial deployment or if policies were removed. The last Lambda modification was 2026-10-18, but policy changes are not shown in the recent_changes output window.&lt;/uncertainty&gt;
