# INC-26a17822: Lambda function cloudops-ai-app-dev cannot write to DynamoDB due to missing IAM permissions.

**Severity:** critical

> Opened automatically by cloudops-ai. This PR only documents the incident:
> **no code or infrastructure is changed.** Apply the fix yourself, then merge.

## 🔴 Error

```
[ERROR] ClientError: An error occurred (AccessDeniedException) when calling the PutItem operation: User: arn:aws:sts::<x>:assumed-role/cloudops-ai-app-dev-exec-role/cloudops-ai-app-dev is not authorized to perform: dynamodb:PutItem on resource: arn:aws:dynamodb:eu-west-<x>:<x>:table/shop-items-cloud-ops-ai-app-dev because no identity-based policy allows the dynamodb:PutItem action
```

## 💥 Impact

All invocations of the Lambda function fail (100% error rate). The application cannot persist data to the shop-items-cloud-ops-ai-app-dev DynamoDB table, affecting all users/services dependent on this Lambda function's PutItem operations.

## 🔍 Root cause

- **99%** IAM policy granting dynamodb:PutItem permission is missing or was removed from the role cloudops-ai-app-dev-exec-role

**Evidence**

- Log shows repeated AccessDeniedException: 'not authorized to perform: dynamodb:PutItem on resource: arn:aws:dynamodb:eu-west-1:523987126142:table/shop-items-cloud-ops-ai-app-dev'
- Metrics show 4 invocations in last hour with 4 errors (100% error rate)
- get_role_policies shows only AWSLambdaBasicExecutionRole attached (CloudWatch Logs only)
- IAM simulator confirms implicitDeny on dynamodb:PutItem for the table
- Lambda config shows DYNAMODB_TABLE_NAME env var is configured but role lacks permissions

## 🛠 Proposed fix

Attach an IAM policy to role cloudops-ai-app-dev-exec-role that grants dynamodb:PutItem (and likely dynamodb:GetItem and other required DynamoDB actions) on the resource arn:aws:dynamodb:eu-west-1:523987126142:table/shop-items-cloud-ops-ai-app-dev. This can be done either by: (1) attaching an inline policy with appropriate DynamoDB actions, or (2) using a managed policy like AmazonDynamoDBFullAccess (if least privilege allows), or (3) creating a custom managed policy with minimal required actions (PutItem, GetItem, Query, Scan as needed by the application). The policy should be attached via AWS IAM console or CloudFormation/Terraform IaC configuration.

## ❓ Uncertainty

None. The root cause is definitively confirmed: the role lacks any DynamoDB permissions despite the Lambda code requiring them.
