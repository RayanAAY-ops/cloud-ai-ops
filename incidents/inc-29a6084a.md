# INC-29a6084a: Lambda function unable to write to DynamoDB due to missing IAM permissions in execution role.

**Severity:** high

> Opened automatically by cloudops-ai. This PR only documents the incident:
> **no code or infrastructure is changed.** Apply the fix yourself, then merge.

## 🔴 Error

```
[ERROR] ClientError: An error occurred (AccessDeniedException) when calling the PutItem operation: User: arn:aws:sts::<x>:assumed-role/cloudops-ai-app-dev-exec-role/cloudops-ai-app-dev is not authorized to perform: dynamodb:PutItem on resource: arn:aws:dynamodb:eu-west-<x>:<x>:table/shop-items-cloud-ops-ai-app-dev because no identity-based policy allows the dynamodb:PutItem action
```

## 💥 Impact

All requests to the cloudops-ai-app-dev Lambda function that attempt to write data to DynamoDB are failing. This blocks the core functionality of the application, preventing data persistence and causing end-to-end service failure for users.

## 🔍 Root cause

- **99%** Missing inline policy or managed policy granting DynamoDB permissions to the Lambda execution role
- **5%** Recent role policy removal or modification (though CloudTrail shows no recent changes)
- **1%** Wrong role attached to Lambda function

**Evidence**

- AccessDeniedException: dynamodb:PutItem not authorized on arn:aws:dynamodb:eu-west-1:523987126142:table/shop-items-cloud-ops-ai-app-dev
- IAM role cloudops-ai-app-dev-exec-role only has AWSLambdaBasicExecutionRole attached (CloudWatch Logs only)
- Permission check confirms implicitDeny for all DynamoDB actions (PutItem, GetItem, UpdateItem, DeleteItem)
- Error occurs in app.py line 21 during table.put_item() call

## 🛠 Proposed fix

Add an inline policy or attach a managed policy to the IAM role cloudops-ai-app-dev-exec-role that grants DynamoDB permissions. The policy must allow dynamodb:PutItem (and other required actions like GetItem, UpdateItem if used) on the specific DynamoDB table resource arn:aws:dynamodb:eu-west-1:523987126142:table/shop-items-cloud-ops-ai-app-dev. Example inline policy: { \"Version\": \"2012-10-17\", \"Statement\": [ { \"Effect\": \"Allow\", \"Action\": [ \"dynamodb:PutItem\", \"dynamodb:GetItem\", \"dynamodb:UpdateItem\", \"dynamodb:Query\", \"dynamodb:Scan\" ], \"Resource\": \"arn:aws:dynamodb:eu-west-1:523987126142:table/shop-items-cloud-ops-ai-app-dev\" } ] }. Apply this to the role in AWS IAM console or via Infrastructure-as-Code.

## ❓ Uncertainty

No recent configuration changes detected in CloudTrail, suggesting this may be a new deployment or initial configuration oversight rather than a regression.
